# AI-Assisted Wake-Up Scheduling for Internet of Things Systems Under Per-Sensor Energy Constraints

Simulator, experiments and paper source for

> **AI-Assisted Wake-Up Scheduling for Internet of Things Systems Under Per-Sensor Energy Constraints**
> Seyed Salar Sefati, Sanda Osiceanu Maiduc, and Razvan Craciunescu. Submitted to IFIP WONS 2027.

A sink with a wake-up radio decides, in every time slot, which battery-powered sensors to wake so
that its estimate of each monitored quantity stays within a tolerance `eps`, while every sensor stays
within its own energy budget. The proposed policy, FG-Wake (forecast-guided wake-up),

1. forecasts each sensor's volatility from irregularly spaced polls (per-sensor scale x shared
   time-of-day profile),
2. learns online a calibrated probability that the estimation error exceeds `eps`
   (logistic calibration with a monotonicity projection),
3. ranks sensors by a renewal index that compares polling now with waiting, and
4. charges each sensor an energy price from a virtual queue whose credit/debt window of `S` polls
   guarantees that no sensor exceeds its budget by more than `S + 1` polls.

## Repository layout

```
code/
  sim.py               slot-level simulator: pull policies (RR, schedules, RND, MaxVar, FG-Wake and
                       its ablations, oracle) and the push baseline (dual prediction, DPS)
  prep_intel.py        Intel Lab trace -> 1-minute temperature matrix + observation mask
  run_experiments.py   all experiments of the paper (writes results/*.json)
  make_outputs.py      results/*.json -> tex/numbers.tex, tex/table_*.tex, tex/fig_*.pdf
data/                  pre-processed trace windows (generated by prep_intel.py, not tracked)
results/               raw JSON results of every run used in the paper (val*.json: validation runs)
tex/                   LaTeX source of the paper (IEEEtran); numbers.tex, tables and Figs. 2-4 are generated,
                       Fig. 1 (fig_pipeline.png) is a static diagram
```

Every number in the paper is a LaTeX macro in `tex/numbers.tex`, generated by `code/make_outputs.py`
from `results/*.json`. No number is typed by hand.

## Reproduce

```bash
# 1. data: download data.txt.gz from https://db.csail.mit.edu/labdata/labdata.html, unzip, then
python3 -I code/prep_intel.py /path/to/data.txt data                     # main window (2004-02-29, 28 motes)
python3 -I code/prep_intel.py /path/to/data.txt data 2004-03-10 _heldout  # held-out window (2004-03-12, 8 motes)

# 2. hyper-parameter selection on synthetic validation seeds 100-104 (optional: the selections used in
#    the paper are included as results/val_best.json and results/val_best_myopic.json)
cd code
python3 run_experiments.py val val_myopic
#   rule: S fixed to 10 polls by design (allowed budget deviation); V, eta and B chosen by the lowest
#   mean validation violation ratio (grids in run_experiments.py: GRID_FG, GRID_MYO).

# 3. experiments (about 1-1.5 h on 2 cores; synthetic parts do not need the trace)
python3 run_experiments.py main diag runtime eps headroom budget alpha sched robust

# 4. numbers, tables, figures and PDF
python3 make_outputs.py
cd ../tex && latexmk -pdf main.tex
```

`make_outputs.py` also reads the trace files in `data/`, so run step 1 before step 4.

## Evaluation protocol (summary)

- **Energy:** one poll costs `1 + alpha` (sensing + one transmission). All policies are compared at the
  same per-sensor budget; realised energy is reported (column `E/B` in Table II).
- **Trace handling:** gaps in the Intel data are interpolated only so that the simulation can run. A
  poll (or a push-side sample) in a minute without a recorded reading fails, so it costs energy but
  returns nothing. Only observed minutes are scored.
- **Tuning:** FG-Wake's `(V, eta, B)` were selected on synthetic validation seeds only. The design
  (trend estimator, calibration layer, shared profile) was developed while inspecting the main trace
  window; the held-out window was not used for any design or tuning decision.
- **Baselines tuned in hindsight** (DPS, the hindsight schedule) choose their parameters on the evaluation
  data itself and are therefore optimistic references.

## Main results (Table II of the paper, violation ratio in %, lower is better)

| Policy | Intel main | Intel held-out | Synthetic |
|---|---|---|---|
| RR (periodic) | 11.67 | 9.65 | 4.16 |
| Schedule from warm-up day | 10.57 | 8.72 | 2.89 |
| DPS (push, hindsight) | 9.97 | 7.52 | 3.19 |
| **FG-Wake** | **9.88** | **7.73** | **3.03** |
| Schedule fitted in hindsight | 9.22 | 7.12 | 2.45 |

FG-Wake beats periodic polling and the schedule calibrated on a warm-up day on the trace. A schedule fitted
in hindsight does better, and push is on par. FG-Wake loses when the budget is too small for the
tolerance. See Sections VI and VII of the paper for the limits.
